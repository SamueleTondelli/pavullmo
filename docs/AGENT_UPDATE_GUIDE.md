# Agent Guide: Updating the PavuLLMo Experiment Tracker Website

This guide is written for teammates' coding agents tasked with adding new **model & optimizer versions**, **training runs**, or **ablations** to the static GitHub Pages tracker on `main`.

---

## 1. File Map & Ownership

| Path | Purpose | Edit directly? |
|---|---|---|
| `docs/data/tracker.json` | Canonical dataset (`model_versions`, `training_runs`, `ablations`) | Yes (or via CLI) |
| `docs/data/tracker.js` | Offline `window.PAVULLMO_TRACKER_DATA` mirror loaded by `index.html` | **No** — generated by `tools/update_tracker.py` |
| `tools/update_tracker.py` | Pure-Python stdlib CLI (`validate`, `build`, `add-version`, `add-run`, `add-ablation`) | Only if extending schema/ingestion |
| `docs/index.html`, `docs/styles.css`, `docs/app.js` | Zero-dependency static frontend (renders directly from `tracker.js` / `tracker.json`) | Only for UI changes |
| `tests/test_tracker.py` | Unit tests for validation, invariants, and CLI ingestion | Yes, if schema changes |
| `.github/workflows/pages.yml` | Validates tracker bundle and deploys `docs/` to GitHub Pages on push to `main` | Only for CI/Pages changes |

> **Hard rule:** `docs/data/tracker.js` must stay byte-identical in parsed JSON content to `docs/data/tracker.json`. The GitHub Actions workflow runs `python3 tools/update_tracker.py validate` and fails if they are out of sync.

## 2. Git & Branch Workflow (Critical)

The repository contains diverged experiment branches (`model/icl-maxxing`, `pretrain-scaling`, `pretrain-evaluation`, `dataset/*`, etc.). **Never merge an experiment branch into `main` just to update the website.**

1. **Read experiment outputs without changing `main`'s codebase:**
   - Local generated runs/results in `artifacts/` are gitignored and remain on disk when switching branches.
   - Committed notes, configs, or CSVs on another branch can be read safely from `main` via:
     ```bash
     git show <branch>:<path/to/file>
     # Example:
     git show origin/model/icl-maxxing:notes/icl_maxxing_35m_experiment.md
     ```
2. **Switch to an up-to-date `main` (or a small PR branch off `main`):**
   ```bash
   git fetch origin
   git checkout main
   git pull --ff-only origin main
   # Optional if using PRs: git checkout -b docs/update-tracker-YYYYMMDD main
   ```
3. **Make sure your commit only touches tracker files** (typically `docs/data/tracker.json` and `docs/data/tracker.js`). Never commit anything under `artifacts/`.

## 3. CLI Usage (`tools/update_tracker.py`)

`tools/update_tracker.py` uses **only the Python 3 standard library** (`python3`, no `.venv` or extra packages required).

> **Important CLI syntax note:** Global flags (`--data`, `--js`) must appear **before** the subcommand (`python3 tools/update_tracker.py --data ... add-run ...`). In normal repository usage, omit them to use the default paths `docs/data/tracker.json` and `docs/data/tracker.js`.

### A. Decide Whether to Reuse or Add a `model_versions` Entry

Every training run requires a valid `version_id` referencing `model_versions[].id`.

- **Reuse an existing `version_id`** if the run uses the exact same architecture dimensions, tokenizer, positional encoding, attention variant, optimizer setup, LR, schedule, weight decay, batch size, initialization, and EMA recipe (even if the dataset or token count changed).
- **Add a new `model_versions` entry** if any architectural hyperparameter, tokenizer, positional encoding, attention layout, optimizer/LR/schedule/WD, batch size, or EMA setting changed.

Naming & data rules for `model_versions`:
- `id`: short lowercase slug, e.g. `v7-gqa-100m` or `v6-iclmax-35m-noema`.
- `commit` & `branch`: use the **actual 7-character git commit SHA** and branch name where that model/optimizer code or preset lives.
- `total_params`: exact integer parameter count (not approximate).
- `params_label`: human-readable string like `"34.23M"` or `"105.40M"`.

```bash
python3 tools/update_tracker.py add-version \
  --id "v7-gqa-100m" \
  --name "100M GQA-2 + Muon + EMA" \
  --commit "1a2b3c4" \
  --commit-date "2026-11-28" \
  --branch "model/scale-100m" \
  --total-params 105400000 \
  --params-label "105.40M" \
  --layers 16 \
  --embed-dim 768 \
  --ffn-type "SwiGLU" \
  --ffn-dim 2048 \
  --seq-len 1024 \
  --vocab-size 16384 \
  --tokenizer-type "SentencePiece BPE" \
  --tokenizer-artifact "production_16k" \
  --pos-encoding "RoPE (base=50,000)" \
  --attention-variant "GQA-2 (12Q/6KV, d_head=64), QK-Norm, Split QKV, Native SDPA" \
  --optimizer-summary "Muon (eff. LR 1.2e-3, WD 0.10) + AdamW (LR 2.4e-3, emb WD 0.02), WSD 60/40, BS 32, EMA 0.9995" \
  --optimizers "Muon (hidden 2D matrices) + AdamW (embeddings, norms, biases)" \
  --lr "Peak LR 2.4e-3 (AdamW), Muon mult 0.5 (eff. 1.2e-3); min LR 0.0" \
  --schedule "WSD 60/40 (warmup 250 steps, 40% linear decay)" \
  --weight-decay "Muon WD 0.10; AdamW emb WD 0.02 (embedding_weight_decay=true)" \
  --batch-size "Eff. BS 32 (32,768 tok); grad clip 1.0" \
  --init "gpt_scaled (std=0.02)" \
  --ema "FP32 EMA decay 0.9995 (warmup enabled)" \
  --notes "Short description of what changed in this version."
```
*(Pass `--untied-embeddings` only if embeddings and LM head are not tied; pass `--replace` to update an existing `id`.)*

### B. Add a Training Run (`add-run`)

**Scope:** Table 2 tracks **curated milestone and evaluated runs** (full pretraining runs, final ablations, or benchmark-evaluated checkpoints) — do **not** clutter it with smoke tests or multi-point short hyperparameter grids (summarize sweeps as an ablation in Table 3 instead).

`add-run` supports automatic extraction from `pretrain_runs.csv`, evaluation summary JSONs (such as `artifacts/results/35m_icl_maxxing_1b_eval.json`), and `artifacts/benchmarks/scores/` directories:

```bash
# Option 1: Ingest from pretrain_runs.csv + eval JSON (recommended when available)
python3 tools/update_tracker.py add-run \
  --id "100m_fineweb2hq_1b_ema" \
  --name "100m_fineweb2hq_1b (Final EMA)" \
  --date "2026-11-28" \
  --version-id "v7-gqa-100m" \
  --dataset "FineWeb2-HQ Italian (train_full)" \
  --tokens "1.00B tok" \
  --from-csv artifacts/results/pretrain_runs.csv \
  --experiment "100m_fineweb2hq_1b" \
  --eval-json artifacts/results/100m_fineweb2hq_1b_eval.json \
  --eval-key final_ema \
  --test-scope "full 10M untouched" \
  --notes "61,035 steps on Modal L4; EMA beat raw weights on val, test, and benchmarks."
```

```bash
# Option 2: Ingest benchmark scores directly from artifacts/benchmarks/scores/
python3 tools/update_tracker.py add-run \
  --id "35m_new_run" \
  --name "35m_new_run" \
  --date "2026-11-28" \
  --version-id "v6-iclmax-35m" \
  --dataset "FineSynth v2 (1.00B)" \
  --tokens "1.00B tok" \
  --train-loss 2.9120 \
  --val-loss 2.9850 \
  --val-scope "full 10M" \
  --test-loss 3.0010 \
  --test-scope "full 10M untouched" \
  --benchmarks-dir artifacts/benchmarks/scores \
  --benchmark-model "35m_new_run" \
  --notes "Summary of setup and takeaways."
```

Important conventions for `training_runs`:
- **Losses are cross-entropy in nats/token** (not perplexity; the UI computes `PPL = exp(loss)` automatically).
- **Always note the evaluation scope** via `--val-scope` and `--test-scope` (e.g. `"full 10M"`, `"full 10M untouched"`, `"prefix"`, `"sampled"`, `"full scaling"`). If `--from-csv` provides a training-prefix val loss and `--eval-json` provides `full_val_loss`, `add-run` automatically stores the prefix loss in `val_loss_prefix` and sets `val_loss` to `full_val_loss`.
- **Benchmarks are 0–1 floats representing macro bidirectional accuracy** (e.g. `0.3996` displays as `39.96%`), **never** percentages like `39.96` and never loss values.
- **EMA vs Raw weights:** If both final EMA and final raw checkpoints are evaluated, log them as separate entries (e.g., `<run>_ema` / `<run>_raw` with `(Final EMA)` / `(Final Raw)` in `name`).
- `add-run` automatically keeps `training_runs` sorted newest-first by `date`. Pass `--replace` to update an existing `id`.

### C. Add an Ablation (`add-ablation`)

Document every controlled experiment or corpus/evaluation study as a concise row in Table 3:

1. Check the highest existing `ABL-XX` ID in `docs/data/tracker.json` (currently `ABL-18`) and increment sequentially (`ABL-19`, `ABL-20`, ...).
2. Choose exact allowed values:
   - `--category`: one of `Architecture`, `Optimizer & Schedule`, `Tokenizer`, `Dataset & Cleaning`, `Evaluation`
   - `--status`: one of `Promoted`, `Rejected`, `Diagnostic`, `Mixed`, `Promising`
3. Include concrete quantitative comparisons in `--results`, a clear takeaway in `--conclusion`, and the note/artifact/commit path in `--source`.

```bash
python3 tools/update_tracker.py add-ablation \
  --id "ABL-19" \
  --date "2026-11-28" \
  --title "Gated Attention Output Projection at 35M" \
  --category "Architecture" \
  --status "Promising" \
  --testing "Compared head-specific sigmoid attention-output gating vs standard SDPA on 12x448 GQA-2 over 200M tokens (seeds 42, 43)." \
  --results "Gated attention improved full 10M val loss by -0.012 nats (3.241 -> 3.229) and reduced gradient-clipping fraction from 0.8% to 0.2%." \
  --conclusion "Promising stability and quality gain; schedule a 1B-token confirmation run before making it default." \
  --source "notes/gated_attn_ablation.md"
```

### D. Manual Editing Workflow (Optional)

If you edit `docs/data/tracker.json` directly (e.g. fixing a typo or adding multiple entries in bulk), regenerate `docs/data/tracker.js` and update `updated_at`:

```bash
python3 tools/update_tracker.py build --touch-date
```

## 4. Schema & Validation Invariants

`python3 tools/update_tracker.py validate` enforces all of the following rules:

1. **Top-level keys** must exist: `project`, `repo_url`, `updated_at` (`YYYY-MM-DD`), `benchmark_note`, `model_versions` (non-empty), `training_runs` (non-empty), `ablations` (non-empty).
2. **Unique IDs** within each of `model_versions`, `training_runs`, and `ablations`.
3. **Referential integrity:** every `training_runs[].version_id` must match an existing `model_versions[].id`.
4. **Dates:** every `commit_date`, `training_runs[].date`, `ablations[].date`, and `updated_at` must be valid ISO `YYYY-MM-DD`.
5. **Numeric checks:**
   - `model_versions[].total_params` must be a positive integer (`int`, not `bool`/`float`).
   - `train_loss`, `val_loss`, `val_loss_prefix`, `test_loss` must be `null` or non-negative numbers.
   - `benchmarks` must be `null` or an object containing all 7 keys (`overall_bidir`, `icl`, `knowledge`, `language_manipulation`, `math`, `math_languages`, `reasoning`), each a float in `[0.0, 1.0]`.
6. **Enums:** `ablations[].category` and `ablations[].status` must match the allowed values in §3C.
7. **JS bundle sync:** `docs/data/tracker.js` must exist, declare `window.PAVULLMO_TRACKER_DATA = ...;`, and parse to the exact same object as `docs/data/tracker.json`.

---

## 5. Verification & Deployment Checklist

Run these checks locally before committing and pushing to `main`:

```bash
# 1. Validate JSON schema, foreign keys, and JS sync
python3 tools/update_tracker.py validate

# 2. Run tracker unit tests (stdlib only)
python3 -m unittest discover -s tests -p 'test_tracker.py' -v

# 3. Optional JS syntax check (if Node.js is installed)
node --check docs/data/tracker.js docs/app.js

# 4. Preview locally in a browser
python3 -m http.server -d docs 8000
```

Then verify your git diff touches only the intended files and push to `main`:

```bash
git status -s
git diff --stat
git add docs/data/tracker.json docs/data/tracker.js
git commit -m "Update experiment tracker with <short summary>"
git push origin main
```

Pushing changes under `docs/**` to `main` automatically triggers `.github/workflows/pages.yml` (`build` -> `deploy`) and updates the live GitHub Pages site.
